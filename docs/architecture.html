Android · Kotlin · Architecture Reference

Cliff.
a streaming voice pipeline

A real-time voice assistant that streams end to end — microphone into Deepgram Flux, final transcripts into Claude over SSE, response deltas straight into Aura-2 TTS as they arrive, with barge-in that cancels mid-sentence. The result feels like conversation, not turn-taking.

STT · Deepgram Flux LLM · Claude Haiku 4.5 TTS · Aura-2 UI · Compose + M3 Net · OkHttp WS/SSE DB · Room
Read from source, not the README. This working tree is pinned to Japanese end to end — claude-haiku-4-5, flux-general-multi with language_hint=ja, and the aura-2-uzume-ja voice. The STT hint, the system prompt, and the TTS voice must all agree, because the Aura-2 voice is fixed for the life of its socket.

The real-time pipeline

One turn flows left to right. Nothing waits for a full result: transcripts stream while you speak, tokens stream while Claude thinks, and audio synthesizes while tokens arrive. Colors below map each stage to its owning component.

→
Barge-in ⟲

BargeInController straddles the whole pipeline. On UserStart it arms a 150 ms debounce; if you're still talking after it, llm.cancelResponse() kills the in-flight SSE request and tts.stop() squelches playback — drop incoming PCM, pause+flush the AudioTrack, send Clear. UserStop disarms it. That's how you cut Cliff off mid-sentence.

04

Auth & security model

No long-lived API keys ever touch the device, and the backend keeps no state. The app authenticates with two shared secrets and mints short-lived (10 min) Deepgram and Claude credentials on demand, cached in memory.

Two shared secrets

Requests carry a secret path segment in the URL (CLIFF_SECRET_PATH) and an app-key header (X-Cliff-App-Key / CLIFF_APP_KEY). Both come from BuildConfig and must match the server — no device identity, no bearer token, no server-side state.

Startup preflight

On launch the app mints a Deepgram token to confirm the backend is reachable and the app key is accepted. Success → Ready (the token is cached for the first session); failure → an error screen with Retry.

Mint & cache per credential

PrefsRepository fetches a Deepgram access token and a Claude API key from the backend, caching each in memory and re-minting ~30 s before it expires.

Build-time secrets: CLIFF_PREFS_BASE_URL, CLIFF_SECRET_PATH, and CLIFF_APP_KEY come from local.properties / env vars into BuildConfig. The app key rides in the X-Cliff-App-Key header on both mint endpoints.

06

Backend contract

Cliff is client-only. It expects just these two endpoints under /api/{secret_path}; a stateless FastAPI reference lives in server/. The backend holds the real Deepgram & Anthropic keys and hands out ephemeral ones. Every request carries the X-Cliff-App-Key header.

MethodPathAuthPurpose
POST/deepgram/tokenApp-KeyMint a short-lived Deepgram token (STT + TTS) via Deepgram's grant API.
POST/claude/api-keyApp-KeyReturn the Claude API key for the Messages API.
